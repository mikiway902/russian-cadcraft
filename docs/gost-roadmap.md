# План развития CADCraftGOST

Цель: реализовать перечисленные возможности поэтапно, не считать весь план выполненным по завершении отдельного этапа. Это собственная реализация по публичным требованиям, не копирование кода, библиотек оформлений или закрытых ресурсов КОМПАС-3D.

## Состояние текущего этапа

Подключены команды книги чертежей, геометрические проверки и инженерные обозначения.
Этапы ниже остаются незавершёнными до полной проверки интерфейса и сохранения.
`requirements.rs`, `specification.rs` и диалог `gost_book.rs` сохранены как промежуточная
работа: они ещё не подключены к приложению и не являются доступными пользователю функциями.

## 1. Листы и реквизиты
- [ ] Общие реквизиты документа и синхронизация штампов.
- [ ] Автоматические номера и количество листов; формы первого и последующих листов.
- [ ] Смена формата и ориентации без потери заполненных полей и геометрии.

## 2. Нормоконтроль
- [ ] Пересечения размерных линий, интервалы между размерами, наложения объектов.
- [ ] Список результатов с переходом к листу и выделением проблемного объекта.

## 3. Инженерные обозначения
- [ ] Параметрическая шероховатость.
- [ ] Параметрические обозначения сварки.
- [ ] Параметрические обозначения резьб.
- [ ] Развитие существующих геометрических допусков для оформления ГОСТ.

## 4. Технические требования
- [ ] Нумерованные требования, редактирование, собственная библиотека типовых текстов.
- [ ] Размещение над штампом, перенос и явная обработка переполнения.

## 5. Спецификация
- [ ] Разделы спецификации на существующих таблицах и извлечении атрибутов.
- [ ] Устойчивые связи деталей и позиций; согласованная перенумерация и обновление количества.

## 6. Ассоциативные осевые
- [ ] Перестроение осевых при изменении исходной окружности/дуги; обработка удаления и копирования.

## 7. Ассоциативные виды из 3D
- [ ] Геометрическое ядро для построения видов и сечений.
- [ ] Проецирование и удаление скрытых линий.
- [ ] Ассоциативные виды, разрезы и устойчивые ссылки размеров на исходную геометрию.

## Приёмка каждого этапа
- Одна реализация команд для GUI, CLI, скриптов и MCP; программные вызовы не открывают диалоги.
- Проверяемое поведение без заглушек, фиктивных результатов и молчаливой потери данных.
- Undo/redo, сохранение и повторное открытие DXF, корректный PDF, ограничение ресурсов и отказ на некорректном вводе.
- Проверка изменённого интерфейса в работающем приложении.
- Регрессионные тесты для выявленных ошибок и неочевидных потребительских сценариев; документация фактических ограничений.

Настройка установщиков через GitHub Actions остаётся отдельной задачей и ждёт отдельной команды владельца.
