# Архитектура CADCraftGOST

## Действующее основание

Исходная архитектура CADCraft описана в [docs/architecture.md](docs/architecture.md). `geom` → `doc/color` → `fonts/render/constraints` → `io` → `engine` → `ui-egui/mcp` → приложения. Документ — copy-on-write `Drawing`; команды JSON и интерактивные машины используют один `Session`. Отмена сохраняет состояние документа, а не выполняет обратную геометрию.

## Реализованные компоненты на исходной точке

| Компонент | Расположение | Назначение |
|---|---|---|
| Команды ГОСТ | `crates/engine/src/cmd/gost.rs`, `gost/*.rs` | Профиль ЕСКД, книга листов, инженерные знаки, требования, спецификации, нормоконтроль |
| Сохранение параметров | `gost/data.rs` | Версионированные записи в DXF xdata `CADCRAFTGOST` |
| Многогранные проекции | `crates/geom/src/drafting3d.rs`, `gost/projection.rs` | Существующие виды/сечения замкнутых сеток; не B-Rep и не источник точных STEP-чертежей |
| Интерфейс ГОСТ | `crates/ui-egui/src/managers/gost*.rs` | Тонкие диалоги над теми же engine-командами |
| CLI/MCP | `apps/cadcraft-cli`, `crates/mcp` | Общий реестр команд, без открывания диалогов из JSON |
| Шрифт | `assets/fonts/opengost`, `crates/fonts` | Офлайн OpenGost Type B, OFL-1.1, разрешённое исключение форка |

## Ограничения подключения

Сейчас ГОСТ-команды и post-command-проходы зарегистрированы напрямую. Это не Plugin API. Бизнес-логика не зависит от egui, но жизненный цикл расширений и режим без ГОСТ требуют переработки. Сначала вводится минимальная регистрация компилируемых расширений, без динамического ABI и повторного интерфейса команд.

### Изоляция продуктовых значений по умолчанию

`Session::empty`, `Session::new` и `Session::new_drawing(metric)` сохраняют нативные контракты CADCraft. `Session::new_document(Drawing)` принимает уже подготовленный документ с чистой базой Undo/сохранения. Продуктовые хосты явно выбирают `engine::extensions::session()` (Start) или `new_session()` (CLI/MCP). Политика сохраняется на время сессии; `NEW` выбирает её, но явные дюймовые документы и открытые файлы не преобразуются. Это не заменяет ещё не реализованное отключение реестра команд и post-command-проходов.

## Целевая ответственность

- SolidCraft/SolidCore: параметрическое моделирование, B-Rep, STEP/IGES, детали и сборки.
- Drawing Extension: получение точных проекций, разрезов, геометрических ссылок и измерений; отображение редактируемыми сущностями CADCraft.
- GOST Extension: нормативные профили, оформление, аннотации, требования, спецификации и нормоконтроль.
- CADCraft: 2D-документ, существующий рендерер, обмен, команды, транзакции и пользовательский интерфейс.

Выбор между библиотечным подключением и отдельным процессом SolidCraft не принят без рабочего прототипа. Протокол должен иметь версию, единицы, устойчивые идентификаторы исходной геометрии, сведения об источнике и явные ошибки; обычный DXF без метаданных этого не обеспечивает.

## Инварианты перехода

1. Работающие команды и сохранённые DXF не удаляются до равноценной проверенной замены.
2. Изменение модели, видов, аннотаций и спецификации — одна транзакция с откатом при ошибке.
3. Нет циклов зависимостей и UI-зависимостей ниже UI-слоя.
4. Входные данные и бюджеты геометрии ограничены; неоднозначная ссылка не перепривязывается молча.
5. Нет собственного параметрического 3D-редактора, нового твердотельного ядра или замены рендерера.
6. Работа офлайн; облачный ИИ не обязателен.
7. Точная геометрия и редакции стандартов подтверждаются отдельными проверками, не названием профиля.
